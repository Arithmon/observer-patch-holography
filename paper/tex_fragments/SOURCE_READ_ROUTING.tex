\subsection{Conditional full-family routing on the wired support}
\label{sec:source-read-routing}

Fix the prepared golden record family at $q=13$ or $q=21$. Supply
protected local addresses, payload versions and zeros;
local record export to an owned port, zero reset, factor-two capture,
integer accumulation and immutable commits; an injective host placement,
the complete preceding-layer metric read menu, and a fixed serial schedule.
These are supplied classical operations and control data.  The construction
does not derive their selection from A1--A3.

The public simulator's geometric assignment applied to all shared-vertex
cell pairs reproduces the captured W12 level-three fixture exactly.  Its
level-four and level-five extensions have respectively $5120$ and $20480$
carriers.  The source sites are assigned injectively by exact golden-coordinate
Morton order to the first $q^3$ hosts.  This is a declared placement, not an
identification of the spherical host coordinates with the source metric.

For each immutable source version, form an ascending-neighbour breadth-first
tree and retain the union of its paths to all required receivers.  Traverse
the retained tree in breadth-first order.  Each seam exports its source
archive, resets its receiver from a protected local zero, performs one pair
mean, archives twice the receiver readout, and resets both endpoints.  Every
recipient then adds its delivered value to its local accumulator.  New
versions are committed after the complete layer.  Paths and interfaces are
independent of payload values.

\paragraph{Finite compilation theorem.}
Under these local feedback and scheduling hypotheses, every completed value equals the value of the declared metric-read
recurrence.  This equality holds for arbitrary initial integer values and
integer local-commit interventions in exact arithmetic.  The induced
semantic read-from order on the distinguished publication/commit events is
exactly the layered order.  All intermediate operations are retained.

\paragraph{Proof.}
The source archive remains protected.  Export and receiver reset prepare
$(x,0)$, the mean gives $(x/2,x/2)$, and local factor-two capture stores $x$.
Cleanup restores the used ports.  Induction along the tree transports the
same immutable version to every recipient, including branching relays.
The recipient set is the complete metric menu, with self-read represented
by the source's own archive.  Induction over layers proves the value claim;
the local biases and initial values may be changed throughout this induction.

Label each transported payload by its actual originating logical version;
label accumulator operations by their future commit, and constant
preparations/resets by no logical payload.  Every consumed-writer edge
respects the logical order.  Conversely, every required read has a retained
writer path through export, mean and capture (or the direct self-read) into
the receiver's accumulator and commit.  Path induction gives both
inclusions for the full induced order.  The independent verifier checks
these edge and path hypotheses from the actual register writers at every
primitive. The finite integer six-operation word, its cost, the instantiated
history induction and the abstract order arguments are kernel checked in
\texttt{Geometry/SourceReadRouting.lean}. Native execution is separately
checked code, not a formally verified interpreter. The exact real hop and sharp
additive error law are in \texttt{Geometry/SourceFeedbackTransport.lean}.
The universal intervention statement uses unbounded integers; only the
retained bounded executions are claimed to fit the native 64-bit format.

\paragraph{Executed resource census.}
For $C$ hosts, $n$ source sites, $K$ rounds, $R$ logical reads and $H$ retained
multicast hops, the event count is
\[
  13C+8n+6H+R+2Kn.
\]
Scalar reads number $7H+2R+2Kn$ and writes number
$13C+8n+7H+R+2Kn$.  Protected storage is
$C+6n+(K+1)n+H$ scalars and mutable storage is $12C+n$.
A depth-$d$ read traverses $6d$ transport events plus a local accumulation;
shared prefixes are counted once in $H$.

At $q=13$, each full run has $H=2972512$ and $19113548$ events; at $q=21$,
$H=46288315$ and $292722053$ events.  Maximum requested shortest-path depths
are $44$ and $91$.  Baseline and centre-source intervention runs retain
$1176764$ and $14559225$ logical reads respectively.  These are executed
multicast costs, distinct from one-hop unicast estimates. The four full
histories contain $623{,}671{,}202$ primitive events in total. The
reproduction procedure in \path{code/source_read_routing/} regenerates each
complete event stream from pinned inputs and source. It checks every
decoded phase and whole-stream hash, independently reconstructs the metric
menu, and replays every operation, consumed writer and completed logical
value. This authenticates the full stream without retaining a large
production tape in the repository.

Each explicit event occupies 64 bytes, including its owner, register and
consumed-writer metadata. The archival producer and verifier retain
history-sized register arrays with respective cell sizes 24 and 32 bytes;
routing buffers, arithmetic workspace and runtime overhead are additional.
The run receipts record native allocation requests and a producer peak
resident-memory observation from a separate timed execution. Event replay
does not remeasure that historical host-memory observation or bound the
memory of the combined regeneration pipeline. These software resources
do not identify physical patch capacity.

The $q=13$ baseline comparison also checks the complete metric-read menu
and all $10{,}985$ logical preparation and commit values against the
separately executed record-metric diagnostic. Equality concerns this
logical projection. It does not identify the full primitive order with
the diagnostic's order or with its canonical-only pair-mean trajectory.
The diagnostic's lag-three interval is interior, whereas its lag-four
interval is clipped; compiling its reads preserves this distinction.

\paragraph{Support-distance bound.}
At triangular subdivision level $\ell$, join two distinct carrier faces
when they share a vertex, and let $D_\ell$ denote the graph diameter.
There are $C_\ell=20\,4^\ell$ faces. The four children of one face
intersect pairwise in a midpoint, and every old vertex belongs to a
corner child. A shared vertex of two coarse faces therefore supplies an
edge between suitable children. Lift a coarse path of $d$ edges by moving
within its initial parent to a crossing child, crossing to the next
parent, and repeating, then moving to the requested final child. This
uses at most $2d+1$ edges. The twenty-face base graph has diameter three,
so induction gives
\[
 D_0=3,\qquad D_{\ell+1}\leq2D_\ell+1,
 \qquad D_\ell\leq4\,2^\ell-1.
\]
The base graph, the four-child refinement condition, the abstract
diameter induction and the closed recurrence are separately kernel
checked in \path{Lean/Geometry/SourceRoutingHierarchy.lean}. Their
composition with the concrete triangle graphs is the analytic argument
above; no Lean theorem instantiates those graph identifications at every
level. Exact integer reconstruction checks the faces and undirected
carrier seams against all three captured levels, three through five.
Physical support selection and an all-level geometric assignment to
twelve distinct ports are separate from this combinatorial bound.
For $n>20$, choosing the smallest level with $n\leq C_\ell$ gives
$n\leq C_\ell<4n$, since the preceding level contains $C_\ell/4<n$
faces. The route bounds at $q=13,21$ are respectively 63 and 127 hops.

\begin{proposition}[Sufficient local working storage]
\label{prop:source-routing-live-storage}
Suppose each layer reads only the preceding payload layer, and each
source's pruned multicast tree and recipient accumulations finish before
the next source starts. A store with 23 scalar slots per carrier suffices
for these admitted reads. Slots may be reused after the final admitted
read of their logical version; every primitive event and its consumed
writer remain in the separate history. The bound counts scalar values;
precision, metadata and controller storage are additional resources.
\end{proposition}
\begin{proof}
Give each carrier twelve mutable transport slots, one protected zero,
six address slots, one accumulator, two payload slots indexed by layer
parity, and one relay slot. The live payload layers $k,k+1$ have distinct
parities. Only the current source's relay can be live at each carrier:
its pruned tree visits that carrier at most once, and its complete episode
precedes the next source's episode. All other slot kinds are disjoint.
The slot map is therefore injective on this live set.

Maintain the relation that the physical cell at a live register's slot
equals its logical value, including its writer identifier when required.
A write preserves this relation because no other live register uses that
slot. Retirement restricts the relation to a smaller live set and changes
no admitted read. Induction over writes and retirements proves the claim.
The live-set injectivity and both preservation statements are kernel
checked in \path{Lean/Geometry/SourceRoutingStorage.lean} for an arbitrary
abstract value type. The program's lifetime discipline is a hypothesis;
its attachment to native execution is checked by code and finite replay.
\end{proof}

With $n$ occupied hosts among $C$ carriers, addresses, accumulators and
payload banks need only $9n$ slots, while ports, zeros and relay slots
use at most $14C$. This gives the sufficient occupied-host bound
$14C+9n\leq23C$. The Lean live set permits all slot kinds at every
carrier, so its layout bound is $23C$; its sharper displayed inequality
is an arithmetic corollary, not a formal occupancy theorem. The allocator
in \path{code/source_routing_refinement/} enforces the occupied-host
census and checks each reuse against a separate last-use pass. Both
bounds exclude scalar precision, writer metadata, controller state and
retained audit history. Two payload banks are sufficient; necessity and
optimality are not asserted. Requests for a retired version lie outside
this lifetime interface, even though its historical event remains recorded.

The four complete $q=3$ mapped controls retain $91{,}272$ events. Each
uses $16{,}919$ physical scalar slots, below the bound $18{,}163$, and
reuses 863 of $17{,}782$ logical allocations. Verification decodes the
committed target tapes, compares every source and target opcode, value,
owner and consumed writer, preserves each transport port's identity,
and independently replays the physical store. The source oracle checks
the preparation, complete read menu, interventions and all 6,561 logical
pairs per control. Applying the bound to the supplied $q=13,21$ programs
gives respectively $91{,}453$ and $370{,}069$ working scalar slots.
Those two numbers are bound applications, not executed mapped production
histories or measured process-memory peaks. The archival full-family
executions and their history-sized allocations are distinct from these
small mapped controls.

\begin{proposition}[Raw-operation count and serial duration]
\label{prop:source-routing-raw-count}
Let $N=(K+1)n$ count the distinguished logical publications and commits,
and let $E=13C+8n+2Kn+R+6H$ count all primitive events of the stated
compiler. Then
\[
 Kn\leq R\leq Kn^2,\qquad H\leq Kn(C-1),\qquad
 E\geq3N+13C+5n.
\]
If $w\geq0$ and $|wN-V|\leq\varepsilon$, assigning the same weight to
every primitive event gives
\[
 |wE-V|\geq2V-3\varepsilon.
\]
For a serial layer of $m>1$ primitive events, a positive tick $\tau$ and
duration $\Delta$ satisfying $m\tau\leq\Delta$ obey $\tau<\Delta$.
\end{proposition}
\begin{proof}
Each site's read menu includes itself and has at most $n$ members.
Each source's pruned tree visits at most $C-1$ nonroot carriers, with
shared prefixes counted once. Summing over sites and rounds proves the
read and hop bounds. Substituting $R\geq Kn$ into $E$ proves the event
lower bound. Consequently
\[
 wE-V\geq3wN-V\geq2V-3\varepsilon,
\]
which implies the absolute-error inequality. Positivity gives
$\tau<m\tau\leq\Delta$. These arithmetic statements are kernel
checked in \path{Lean/Geometry/SourceRoutingBudget.lean}; identifying
their counts with the program uses the explicit operation census.
\end{proof}
The raw-mass inequality concerns the whole execution window. It supplies
no count for each interval of the primitive order and excludes no other
event weighting. In particular, the logical count-volume limit cannot
be assigned unchanged to every transport event. Parallel duration
requires a separate scheduling analysis, and neither duration convention
identifies a physical clock.

\paragraph{Scope of the additional law.}
Every closed finite word of pair means preserves total live load.  A reset
that changes that total therefore cannot be such a closed word; the finite
invariant obstruction is also kernel checked.  This excludes this particular
reset realization on that closed register set.  It does not exclude
tomography, changed ancillary state, other feedback, other decoders, or all
admissible realizations of the metric order.

Serial execution, write hazards and custody remain present even when a
constant reset has no prior scratch payload as a semantic parent.  The
serial unit-event duration counts every primitive; no physical time scale
is inferred.  Physical header/address transport is not implemented by the
scalar channel.  Routing events are not the distinguished count-volume
events of the continuity-set theorem.  Selection of the supplied record,
feedback and routing law from the source architecture is not derived.
These conditional finite receipts implement neither a quantum instrument
nor a physical continuum.
